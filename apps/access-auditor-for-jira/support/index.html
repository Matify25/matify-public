Support

Access Auditor for Jira is supported by Matify. One address, read by a person.

Two ways in, both fine

Public tracker. Open a ticket on GitHub — support questions, bug reports and feature requests, with a form that asks for what an answer needs. Reading what is already reported needs no account; opening a ticket needs a free GitHub one.

Email. mira.maty@web.de — no account required, and the right choice for anything you would rather not write in public.

Security

Never report a suspected vulnerability as a public issue. Email mira.maty@web.de with security in the subject line, or use GitHub's private reporting from the security policy. A flaw posted in public is readable by everyone before a fix exists.

Before you write

Two pages answer most questions faster than an email round trip: the troubleshooting page, which lists every error code the app can show and what to do about each, and the FAQ.

What to send

If something went wrong rather than being unclear, include a diagnostic report:

  1. Open the app in Jira and go to the Diagnostics tab.
  2. Select Copy diagnostic report.
  3. Paste it into your email, with a short description of what you expected and what happened instead.

The report is built to contain no personal data and no credentials — no project name, group name, account identifier or permission holder appears in it. It answers most of the questions a first reply would otherwise have to ask.

Reporting a security issue

Please include enough detail to reproduce it. How the app handles data, and what it deliberately does not do, is set out in the security and privacy statement — if you find something that contradicts it, that is worth reporting in itself.

What is not supported

Jira Data Center and Jira Server; the access model of team-managed projects; and any Atlassian product other than Jira Cloud. These boundaries are described in known limitations rather than discovered after purchase.

Access Auditor for Jira is published by Matify for Atlassian Jira Cloud.
