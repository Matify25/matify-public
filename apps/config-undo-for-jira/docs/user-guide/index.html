User guide

Concepts

Configuration types ("families")

Config Undo works with eight types of Jira configuration. Each object has a stable key (for example PS:10000 for permission scheme 10000), shown on its page in Objects & Compare.

Coverage & Health shows the detection mode per type.

Versions

A version is a complete, normalised copy of one object at one point in time. Config Undo stores a new version only when the content changed (the content is hashed; identical content is stored once). Each version has a source:

Backfill (workflow history)a complete earlier workflow version from Jira's workflow history (up to 60 days)
Restorethe state after a restore by Config Undo
Before restorethe live state saved right before a restore wrote anything ("rollback of the rollback")

Manual re-readcaptured by "Compare with live", a preview or the guided test

The change journal and its sources

The journal is one timeline of changes: who changed which object, when, and what changed. Changes come from:

  • the hourly audit-log poll: Config Undo reads new audit records, works out which objects they touch and re-reads exactly those objects;
  • Jira product events for projects, versions, components, fields and field contexts, which arrive within minutes;
  • the rolling reconcile, which re-reads a share of every type each day (all of it once a week on small and medium sites, once every four weeks on large sites) to catch changes Jira did not audit;
  • onboarding backfill from the audit log and workflow history;
  • Config Undo's own restores (marked as the app's own change).

Authors come from the audit log and are stored as Atlassian account ids; names are looked up when you view a page. When Jira's audit record names no author (for example automatic changes Jira makes itself), the author column shows Not recorded by Jira. Changes found by reconcile say "detected by reconcile, author unknown". Some entries carry a High impact marker: a grant removed from Browse projects or Administer projects, a status removed from a workflow, or any change to an object used by more than ten projects.

Restore points

A restore point is a named list of "the version of every object that was current at this moment", for all or some configuration types. When only a few changes are waiting since the last hourly poll (up to 15 objects), creating one captures them first; it then records the list and a freshness time per type. Restore points are created by hand or automatically once a week. Restore points older than the retention period are removed by the weekly maintenance run unless they are pinned; pinned restore points, and the versions they reference, are kept regardless of retention.

Restore requests

A restore request puts one object back to one version. It goes Preview → Request → Approve → Result, and every step is recorded. See the Restore guide.

The ledger

The ledger is an append-only record of every restore request, approval, rejection, expiry, execution, verification result, settings change, data deletion and uninstall. Each entry carries a hash over its core fields (sequence number, time, type, request, object, before and after hash, verification result and the person's token) and the hash of the previous entry. Changing or removing an entry's core fields, or removing an entry, breaks the chain, and the integrity check finds it. People are referenced in the hashed part by a random token, not by their account id, so erasing a closed account keeps the chain verifiable. The entry's short text summary and the plain account id are stored next to the hashed part, so the check does not cover them.

Pages

Journal

  • Summary cards: changes in the last 7 days, unreviewed changes, protected objects.
  • Filters: date range (24 hours, 7, 30 or 180 days, all time, custom), configuration type, author, project, source, review status, change type and a text search on object name. Filters are kept in the URL, so a filtered view can be bookmarked.
  • Open an entry to see the diff, open the object, compare, or start a restore of the earlier version.
  • Review: mark entries Reviewed or Flag with note (one at a time or several selected). The reviewer and time are recorded.
  • Exports: Export CSV, Export JSON (the current filter) and Review report (CSV).

Objects & Compare

  • One tab per configuration type; search with Name contains, filter with Changed (last 7, 30, 90 or 180 days) or Used by project. Only objects Config Undo has already captured are listed; during onboarding the list grows as types are captured.
  • An object's page lists its versions (newest first) with source and time, the projects that use it, and a link to the object in Jira.
  • Compare any two versions, or a version with Live Jira (reads it now). Diffs are specific to the type: grants as permission × holder, recipients per event, workflow statuses and transitions with their rules, screen tabs with ordered fields, options with order and enabled state, project details, role actors, components and versions.
  • Restore this version starts a restore preview (only when restore is enabled for that type).
  • Download any version as JSON, for example to re-create an object by hand.

Restore points

  • Create restore point: label and configuration types.
  • Open a restore point to see its objects, each marked Changed since, Created since, Deleted since or Unchanged, with Compare and Restore buttons. The toggle Only objects changed since the restore point hides the rest.
  • Pin keeps a restore point beyond retention.
  • Re-read everything now (restore points with up to 500 objects) re-reads every object in it from Jira.
  • A weekly automatic restore point is created by the daily run on the chosen weekday (UTC), once onboarding has finished. The exact time can't be set, and a missed weekday is not made up the next day.

Restores

Tabs: Pending approval, In progress, History. A request shows its preview and write plan, reason, requester, approver, a timeline with ledger entry numbers and the verification result. Actions depend on the state: approve, reject (with an optional note), cancel, retry remaining steps, preview again.

Ledger

Entries newest first, with sequence number, time, type, request, object, before and after hash, verification result, actor, entry hash and previous hash. Verify integrity recomputes the chain and reports the first entry that doesn't verify, if any. A long ledger can't be checked within one request: the page then says how many entries verified so far, and the whole chain is then checked again in a background job, with the result shown in Coverage & Health. The chain head (latest entry number and hash) is shown so you can record it outside Jira. Export as CSV or JSON.

Coverage & Health

  • Per configuration type: detection mode, objects and versions captured, last capture and last reconcile, last error. A type with an object Jira refused to show is marked Partly recorded.
  • Onboarding progress with Pause onboarding / Resume onboarding.
  • Import older history (after onboarding): imports audit-log records from before the current history start, as its own background job. Recording, the reconcile and weekly restore points keep running meanwhile.
  • A note when Jira doesn't let the app read the audit log (for example on Jira Free).
  • Audit-log poll status.
  • Rate-limit budget: estimated points per hour for the last 24 hours.
  • Ledger integrity status.
  • Download diagnostics (JSON, no account ids, names or configuration content) for support.

CSV files are UTF-8 with a byte-order mark. Every cell that starts with =, +, -, @, a tab or a carriage return is prefixed with ', so spreadsheet programs don't run it as a formula. Display names are added to journal and review exports when you export; the ledger is exported exactly as stored.

Licensing

Trial and active licences: everything is available; during a trial a banner shows when it ends. Inactive licence: read-only. The journal, versions, compare (without recording new versions), existing restore points, the ledger, exports and Delete all app data stay available. Restores, previews, creating or re-reading restore points, journal reviews, settings changes, Import older history and the guided safe test are blocked, and background recording pauses. After the licence is active again, recording resumes by itself and the next hourly poll catches up on the audit log since the last poll.
