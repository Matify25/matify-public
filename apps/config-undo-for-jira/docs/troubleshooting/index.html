Troubleshooting

Every error Config Undo shows has a code (CUJ-…) and a reference (ref). Send both to support if a problem stays; the reference finds the matching log lines.

Error codes

CodeWhat you seeWhat to do
CUJ-NOT-ADMIN"You need Jira administrator permission to use Config Undo."Only users with the Administer Jira global permission can use the app. The permission is re-checked at most every five minutes. In a restore result it means the approver lost Administer Jira before a background restore started; nothing was written — approve again with a current admin.
CUJ-INVALID-INPUT"The request was not valid. Reload the page and try again."Reload. Also shown when a typed confirmation doesn't match exactly (object name in single-admin mode, DELETE ALL CONFIG UNDO DATA), when a reason is missing, or when a setting is out of range.
CUJ-READ-403"Jira didn't allow Config Undo to read …"In the first minute or two after installation this is normal; Jira is still activating the app's access, and the app retries. Later, check that the app is installed with all its permissions (Manage apps). If one object stays unreadable, its type shows Partly recorded in Coverage & Health and the app retries it.
CUJ-READ-404"Jira couldn't find … It may have been deleted."The object was deleted in Jira. The journal records the deletion. See the restore guide for which deleted objects can be recreated.
CUJ-RATE-429"Jira is rate-limiting apps right now …", "Hourly budget for background work is used up …" or "Config Undo has used this hour's share of Jira's rate limit for comparisons and previews on this site. Try again after HH:MM UTC."Background work resumes automatically (the status chip or the message shows the time). For comparisons, previews, restore points and the guided test, try again at the time shown: they share an hourly cap per site. Approved restores are never blocked by these budgets; a restore write that Jira rate-limits is retried automatically. See Large sites.
CUJ-JIRA-5XX"Jira returned a server error. Config Undo will retry."Wait and retry. If it persists, check Atlassian's status page and contact support with the ref.
CUJ-WRITE-400"Jira rejected the request for …"A restore step was refused by Jira. The result page says which step and the HTTP status; nothing after it was written. Read the result notes, compare with live, and see the Restore guide playbook.
CUJ-WRITE-409"Another configuration change is in progress in Jira. Try again in a moment."Jira is busy with another workflow change. Wait a few minutes and preview again.
CUJ-DEPENDENCY-MISSING"The parent option … wasn't found, so its child options weren't recreated." (in a restore result)A restore of cascading-select options couldn't find the parent option, so its child options weren't created again. Make sure the parent option exists in the field context, then use Retry remaining steps if the result offers it (within one hour), or preview again.
CUJ-VERIFY-MISMATCH"Restored with differences …"Verification found differences. Open the request: it lists what matches and what doesn't. Retry remaining steps within one hour, or follow the playbook.
CUJ-LOCKED"Another restore of this object is running …"Wait until it finishes (Restores → In progress), then try again.
CUJ-STALE-PREVIEW"The live … changed after your preview …" / "This preview is more than an hour old …"Someone changed the object since the preview, or the preview is too old. Preview again and submit a new request.
CUJ-LICENSE-INACTIVE"Restores are paused because the Config Undo licence isn't active." / "Config Undo is read-only while its licence is inactive …"Renew the subscription in Manage apps. Your data stays readable and exportable meanwhile.
CUJ-RESTORE-DISABLED"Restore is off for this configuration type …"A Jira admin can turn it on in Settings → Restore.
CUJ-KILL-SWITCH"All restores are disabled on this site (kill switch) …"A Jira admin can turn off "Disable all restores" in Settings. The kill switch blocks every write, the guided safe test included. A restore that stopped for this reason before its first write changed nothing. One that had already written shows Restored with differences: what was written is verified, not rolled back, and you can retry the remaining steps within one hour after turning the kill switch off.
CUJ-SELF-APPROVAL"A second Jira admin must approve this restore (four-eyes approval)."Ask another Jira admin, or switch to single-admin mode if your site has only one.
CUJ-EXPIRED"The approval window passed."Preview and request again. The window is set in Settings → Approval (1–72 hours).
CUJ-BLOCKEDVarious: "This restore can't run …", "This request was already submitted.", "Another admin is deciding on this request right now. Reload to see the result.", "A retry of this request is already running.", "The retry window (1 hour) has passed …", "Only the guided safe test's own test scheme can be restored without a second approver.", "The test scheme is now used by a project …", "Confirm to …", "An import of older history is already running.", "Re-reading is offered for restore points with up to 500 objects …"The message says why. Reload when another admin is deciding. Blocked restores are explained in the Restore guide.
CUJ-NOT-FOUND"That version no longer exists. It may have been removed by retention." / "Config Undo hasn't captured this object (yet)."Retention removed it, or onboarding hasn't reached it yet (check Coverage & Health). Pin restore points you want to keep.
CUJ-STORAGE"The stored version could not be read." / "Creating the restore point took too long. Try fewer families."Retry. For restore points, choose fewer configuration types. If it repeats, contact support with the ref.
CUJ-UNKNOWN"Something went wrong in Config Undo …"Retry. If it keeps happening, download diagnostics and contact support with the ref.

Common situations

The journal is empty right after installation. Onboarding starts about two minutes after installation and fills the last 30 days first, newest first. The status chip shows the progress. If nothing happens for more than 15 minutes, open Coverage & Health and check whether onboarding is paused.

A change made soon after installation can't be undone. On busy sites the first hour's budget may run out before Config Undo has captured every object (see Getting started). A change to an object that wasn't captured yet appears in the journal from the audit log, but there is no complete earlier version to restore. Objects listed in Objects & Compare can be captured at once with Compare with live.

A change I just made isn't in the journal. The audit log is polled every hour. Open the object in Objects & Compare and choose Compare with live to capture it now. Field schemes are only detected by the reconcile.

A journal entry says "author unknown" or "Not recorded by Jira". "Detected by reconcile, author unknown" means the change was found by the reconcile, not by the audit log, so Jira gave no author. Not recorded by Jira means Jira's audit record for the change names no author (for example a change Jira made itself).

Coverage & Health says Jira didn't let Config Undo read the audit log. This happens on sites where apps can't read the audit log (for example Jira Free). Config Undo still records changes through Jira events and the daily reconcile, without the author, and can't import history from before the installation.

An entry from "Backfill (audit log)" can't be restored. Those entries show what the audit log recorded but contain no complete earlier version.

"Restore this version" is missing. Restore is off for that type (Settings), the type is field schemes, or the licence is inactive.

The approver doesn't see an Approve button. In four-eyes mode the requester can't approve. Pending requests are in Restores → Pending approval for every Jira admin.

Jira's audit log shows "Config Undo" as the author of a restore. The restore ran in the background, either because it was too long to run directly or because it couldn't finish within the approval request (the ledger then shows "Continued in the background as the app"). The ledger records who approved it. See Permissions and security.

A restore stays "In progress" after the page closed. If the approval request ended before the restore finished, a background check finishes it about two minutes later, and an hourly check resumes approved restores that stopped making progress (for example when Jira briefly refused to start the background run; the approval then said the run starts automatically within about two hours). Reload Restores → In progress after a few minutes.

Ledger: "Check still running". The ledger is too long to check within one request. The entries checked so far verify; the whole chain is checked again in the background and the result appears in Coverage & Health.

Ledger integrity check failed. The page shows the first entry that doesn't verify. Don't delete app data; download diagnostics and contact support immediately (security severity).

Onboarding seems stuck. It continues within its hourly budget, and pauses for an hour when Jira's rate-limit pool is under pressure. The hourly poll also restarts onboarding that stopped unexpectedly. Coverage & Health shows the current phase and percentage.

Coverage & Health says "Partly recorded". Jira refused to show one object of that type to the app (HTTP 403), for example a project behind a data security policy. It is skipped, the rest of the type is recorded, and the mark clears once a later read of that object succeeds.

The guided safe test says "No change detected yet". Save your change in Jira, then click "I changed it" again.

What to send to support

  1. Coverage & Health → Download diagnostics (no account ids, names or configuration content).
  2. The error code and ref.
  3. For restores: the request id and ledger entry numbers.
  4. What you did and what you expected.

Email support@matifyapps.de, or use the form or tracker on the support page. Never post account ids, email addresses or configuration content in the public tracker.
