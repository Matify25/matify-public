FAQ

Does any of our data leave Atlassian?

No. Document Generator runs on Atlassian's Forge platform, stores its data in Forge hosted storage and declares no external connections. Documents are built in your browser. Matify sees only anonymous usage counts in Forge logs, and only if your admin allows app log access. Details: Privacy and data.

Does the app keep a copy of our documents?

No. Generated documents are saved by your browser. If you attach one to a work item, Jira stores it as a normal attachment. For background documents, the app keeps the collected Jira data — not the document — for 24 hours after it is ready (or 24 hours after it failed, so it can be retried).

Can a document contain work items I can't see?

No. Every read runs with the permissions of the person who generates the document — background documents too. Work items you can't see are left out. Selected or single work items that can't be read are listed in the result; work items that a search doesn't return can't be listed, because Jira doesn't report them to apps.

Can we use our own Word template?

Yes — that's the point. Add {{placeholders}} to your Word file and upload it; the validator checks it and the preview shows real values before anyone uses it. Start with the Template cookbook or download a curated pack to customise.

Can we use Excel or PowerPoint templates?

No. Templates are Word files. Excel output is a table of work items with typed columns; there is no PowerPoint output.

Why does the PDF look slightly different from the Word document?

PDF is made by Matify's own converter, which reproduces a documented subset of Word with bundled fonts. Line breaks and page counts can differ, and some Word features (text boxes, charts, SmartArt …) are not reproduced. The validator tells you which ones affect your template. Use DOCX for the exact layout — Word's own "Save as PDF" remains available for the DOCX.

Does it support Chinese, Japanese, Arabic or Hebrew?

In DOCX and XLSX the text is kept as it is in Jira. PDF output cannot show these scripts; use DOCX.

How many work items can a document have?

Up to 200 directly (50 with comments) and up to 1,000 in a background document. See Large sites.

Can I make a document from the rows I selected in the issue navigator?

Not at the moment. Selecting rows in the issue navigator does not limit the document; Jira passes the search, not the selection, to apps. Apps → Generate document… uses your current search (JQL), so refine the JQL instead — for example key in (ABC-1, ABC-4, ABC-7). If Jira passes a selection in the future, the dialog offers "Selected work items (n)" automatically.

Can a Jira admin stop someone else's background document?

Yes. Jira settings → Apps → Document Generator → Usage → Background documents lists everyone's background documents. Admins can cancel or delete them after a confirmation, but can't open, render or download another person's document, and the list shows "Another user" instead of a name.

Can we restrict who exports data?

Yes. Jira admins can limit document generation to selected groups, switch formats off, switch attaching off, decide which templates are published to which projects, and lower every limit.

Does Document Generator change anything in Jira?

Only when someone clicks Attach: it adds the document as an attachment to the chosen work item. It never edits fields, comments or statuses and never deletes anything in Jira.

Does it work with Jira Service Management?

Yes, in the agent view. An agent opens a request in a Jira Service Management service project and chooses ••• → Generate document; it works as for any other work item (checked on a Jira Cloud site in October 2026). There is no customer-portal entry point, so customers on the portal don't see the app.

Can documents be created on a schedule, sent by e-mail or by Automation?

Not in this version.

Can we create Confluence pages?

No. Download the document or attach it to a work item.

Can people sign documents?

Templates can contain plain sign-off lines. The app does not collect electronic signatures.

Which browsers are supported?

Chrome, Edge and Firefox (current versions). Safari has not been verified yet — see Known limitations.

Why does Jira ask me to "Allow access" the first time?

Because the app reads work items as you. This is Atlassian's standard consent; accept it once.

Is our data kept in our data residency location?

Yes. Forge hosted storage follows your Jira site's data residency, and all app data is stored there.

What happens when our licence ends?

Nobody can generate new documents. Queued background documents are cancelled, and the collected data of background documents that were ready is deleted, so they can no longer be downloaded. The admin pages stay readable but configuration is read-only; Jira admins can still download, unpublish, archive and delete templates, cancel or delete background documents, and delete all app data. Users can still see, cancel and delete their own background documents in My documents. See the admin guide.

What happens to our templates when we uninstall?

The app's data follows Atlassian's lifecycle for uninstalled Forge apps. Do not rely on a reinstallation to restore — or to remove — earlier data. Download the template versions you want to keep before you uninstall. See the admin guide.

Does the app use AI?

No.

Is there a Server or Data Center version?

No. Document Generator is for Jira Cloud.

Where do I get help?

support@matifyapps.de or the support page. Error codes are explained in Troubleshooting.
