Changelog

1.0.0 — Initial release

First public release of Document Generator for Jira (Word, PDF & Excel).

  • Your own Word templates with a small, documented placeholder language: work item and custom fields with date, number and text formats; document tags; rich text from descriptions, environment, multi-line custom fields and comments; sections for work items, sub-tasks, child work items, links, attachments and comments; grouping by work type, status, status category, fix versions and components; has: conditions; counts, status-category percentages and overdue counts; images; page breaks for one page per work item. See the Template cookbook.
  • Validator that runs before a template can be published: safety checks (macros, encryption, external links, dangerous field codes, embedded objects, zip bombs), syntax with the exact location in the Word file, field names checked against your site, and PDF-compatibility warnings. Every code links to the cookbook.
  • Preview with sample on one work item or up to 20 from a JQL: resolved values, fidelity notes, images, and sample downloads in all three formats.
  • Three formats from one template: DOCX (your exact layout), PDF (built-in converter for a documented subset of Word, bundled Noto Sans fonts) and XLSX (typed columns, frozen header, filters, formula-injection guard).
  • Three entry points: the work item's ••• menu (including the epic hierarchy and sub-tasks), the issue navigator's Apps menu (your current search) and Apps → Document Generator → New document (JQL or saved filter).
  • Download or attach the result to a work item in one click, with a permission check, a duplicate warning and the site's attachment size limit respected.
  • Background documents for up to 1,000 work items: they continue after you close the window, wait for API budget when needed, and are ready in My documents for 24 hours.
  • Four curated packs: Release notes, Status report, Work item record and Test evidence, each with an Excel column set; download any of them to customise.
  • Permission-faithful: every read runs as the person generating the document; background documents read as the person who started them.
  • Admin controls: who may generate (everyone or selected groups), formats, attaching, comments, lower limits, API budget, PDF paper size, default date format, file-name pattern, packs on or off, template-to-project assignment; Overview and Usage pages without personal data; cancel or delete any user's background document without access to its content.
  • Protection of Jira's shared API limit: an hourly budget per site, reservations before every read, and a brake that steps back when the shared limit runs low.
  • Privacy: no external connections, data in Forge hosted storage with data residency, collected data deleted 24 hours after a background document is ready or has failed (earlier on Cancel, Delete now or when the licence ends), weekly personal data reporting, Delete all app data.
  • When the licence is not active: no new documents; admin pages stay readable but configuration is read-only; templates can still be downloaded, unpublished, archived and deleted; users can still see, cancel and delete their background documents; collected data of background documents is deleted. See the Admin guide.

Changes since the pre-release builds (October 2026)

These matter only if you tried an earlier build of the app (for example a test installation):

  • Stricter template safety check. The check now reads every XML part of the template, not only the usual part names, and also rejects hyperlinks to files, network shares or programs (file:, UNC paths, javascript:, ms-msdt: and similar), a hyperlink base on a file share, mail-merge settings, the older INCLUDE field, field names in quotes, field codes built from other fields (a field whose code contains another field, and QUOTE and SET fields), and embedded packages outside the usual folder. The zip-bomb guard now also runs each time a document is generated from a stored template. Some templates that an earlier build accepted can now be rejected — when you upload a new version, and by the output check when documents are generated from them. The message names the element to remove; see E-007.
  • Unlicensed sites: admin configuration is read-only (it was editable before), and ready background documents can no longer be rendered — their collected data is deleted.
  • Admin Background documents no longer shows the titles other users gave their documents.
