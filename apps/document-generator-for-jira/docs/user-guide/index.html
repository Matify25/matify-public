User guide

This guide is for everyone who creates documents. Template management and settings are in the admin guide.

Who can generate documents

Anyone with Browse projects permission on the work items, unless your Jira admin has limited document generation to members of selected groups. In that case people outside those groups see: "Your Jira admin has limited document generation to selected groups. Ask them for access."

The first time you use the app, Jira asks you to allow Document Generator to access Jira on your behalf. This is Atlassian's standard consent for apps that read data as the signed-in person.

Your permissions decide what is in a document

Every Jira read for your document runs as you — never with more rights than you have:

  • Work items you can't see (no Browse permission, issue security, a deleted or moved work item) are left out. Selected or single work items you can't see are listed in the result as "not found or you can't see it"; a search simply doesn't return them, so they can't be listed.
  • Comments with restricted visibility appear only if you can see them.
  • Images are fetched by your browser with your own permissions.
  • If your organisation uses Atlassian data security policies that block apps from certain work items, Jira hides those work items from the app. A selected or single work item is listed as "blocked by your organization's data security policy" only when Jira says so for it — otherwise it appears as "not found or you can't see it". Work items that a search doesn't return can't be listed at all, because Jira doesn't report them to apps.
  • A template published only for certain projects is used only for work items of those projects; work items of other projects are left out and listed.

Background documents read Jira as you too, also after you close the window — see Background documents.

Generate from a work item

Open the work item and choose ••• → Generate document.

The dialog has one screen, from top to bottom:

  1. Template — curated packs and your organisation's templates in two groups. The description and the available formats are shown under the selection. Templates that can't be used here are shown with the reason, for example "Not available for this project" or "Works only for lists of work items".
  2. Format — DOCX (Word), PDF or XLSX (Excel), as allowed by the template and by your Jira admin.
  3. Scope — "This work item", "This work item + sub-tasks", or for a work item with children "Epic + children + sub-tasks".
  4. Options — "Include comments" (only when the template shows comments and your admin allows it; the dialog shows how many recent comments per work item), the document title (used where the template shows {{doc.title}}), and a preview of the file name.
  5. Summary — how many work items the document will contain, the limits that apply, whether comments are included, an estimated time and the share of the site's hourly API budget it uses.

Click Generate. The progress view shows the steps Collecting data, Fetching images, Rendering and Ready. Cancel stops at any time; no file is created.

Generate from a search

In the issue navigator, run a search and choose Apps → Generate document….

  • The action uses your current search (JQL): the document contains the whole search, in the order of your JQL. If your JQL has no ORDER BY, the app sorts by key.
  • Selecting rows in the issue navigator does not limit the document. Jira passes the search, not the selection, to apps. To narrow the document, refine the JQL — for example key in (ABC-1, ABC-4) or an extra condition. The dialog says so under the context line.
  • If Jira does pass selected work items to the app (this may change on Atlassian's side), the dialog also offers the scope "Selected work items (n)": the document then contains exactly those, in the order you selected them.

The dialog is the same as above, with the scope "Whole search (~n)". The count is Jira's approximate count.

A search must have at least one condition — Jira doesn't allow apps to run unbounded searches. A JQL such as ORDER BY created alone is refused with: "This search has no filter, and Jira can't run unbounded searches for apps. Add a condition such as a project, then try again."

The Documents page

Apps → Document Generator has three pages.

New document

Create a document from a JQL search (with Validate JQL) or from one of your saved filters, then continue with the same template, format and options as in the dialog. Use this page when the issue navigator's menu item is not available on your site — the issue navigator integration uses an Atlassian module that is still in preview.

My documents

Your background documents: when they were created, template, scope, formats, number of work items, state, progress and when they expire. Filter by All, Active, Ready, Finished or Failed. Actions: Render & download, Attach, Cancel, Delete now and Retry from checkpoint. If the app's licence has ended, the page shows a notice and only Cancel and Delete now remain; New document is unavailable.

Templates

The templates available to you, with a description, the scope they work for, their formats and — for curated packs — sample files with fictitious data.

Limits

Your Jira admin may have set lower limits. The summary always shows the limits that apply before you start.

When Jira's shared API limit for apps is nearly used up, the app protects it: documents generated now are limited to 50 work items, then to single work items, and background documents wait for the next full hour. The summary tells you when this applies. See Large sites.

If a scope is larger than the background limit, the dialog explains it: "This search has about {n} work items. Documents can include up to {cap} ({format}). Narrow the search, or split it by project or version."

Nothing is left out silently

  • Work items that could not be included are listed in the result ("2 work items were not accessible"), with the reason. A background document lists the first 200 of them; the result and the document notes give the full number ("80 more work items were left out; only the first 200 are listed.").
  • If more than 10 % of the work items can't be included, the app asks before it builds the document: "37 of 400 work items could not be included. Generate anyway?"
  • If none can be included, no document is created.
  • Comment caps, image caps and images shown as placeholders are listed as notes with the result.
  • Templates can print the same list into the document with {{doc.notes}}.

Download

Click Download in the result. Your browser saves the file; the app does not keep a copy. Downloads only start from a click on the button — if your browser blocks downloads for the site, allow them, or attach the document to a work item instead.

Downloads were verified in Chrome on a Jira site, and in Edge and Firefox in a test setup that uses the same browser sandbox as Jira. Safari has not been verified yet; see Known limitations.

Attach to a work item

Click Attach to ABC-123 to add the document to a work item as a normal Jira attachment. For a document made from a search, you choose the target work item; it defaults to the first work item in the document. For a document from a work item or an epic, it defaults to that work item or epic.

  • You need the Create attachments permission on the target work item. Without it the button is disabled and explains why.
  • Your Jira admin can switch attaching off for the whole site.
  • If a file with the same name was attached to that work item in the last 10 minutes, the app asks before attaching another copy.
  • Documents larger than 10 MB ask for confirmation. A document larger than your site's attachment limit can't be attached; download it instead.
  • Attaching never replaces or deletes existing attachments. It is the only change Document Generator ever makes in Jira, and it happens only when you click.

Attached documents are Jira data: they stay in Jira, also when the app is uninstalled.

Background documents

Searches above the direct limit (200 work items by default) run in the background:

  1. Click Run in background and confirm. The app shows the estimated time and that it may wait for API budget.
  2. You can close the window. The app collects the work items in the background, reading Jira as you. Jira applies your current permissions to every batch, so if your access is removed, later batches no longer include those work items.
  3. Follow the progress in My documents:
StateMeaning
QueuedWaiting for another document on this site (one background document collects at a time per site). If the app couldn't hand the next step to Jira's queue, it shows Retry, which continues where it stopped; a daily check also resumes such documents.
Waiting for budgetPaused until the next full hour to stay within Jira's API limits — resumes automatically.
Collectingn of N work items collected.
ReadyThe data is collected. Render it within 24 hours.
Downloaded / AttachedYou rendered and downloaded or attached it. You can render it again until it expires.
FailedStopped after several attempts. Retry from checkpoint continues where it stopped; it is available for 24 hours, and the data collected so far is kept for this time. After that, generate the document again.
CancelledYou or a Jira admin cancelled it, or the app's licence ended (then the collected data, also of a ready document, is deleted).
Expired24 hours after it was ready, the collected data is deleted. Generate it again.
  1. When it is Ready, choose Render & download: your browser builds the document from the collected data, fetches images with your permissions and saves the file. You can also attach it.

Good to know:

  • You can have up to 3 background documents in progress at a time, and a site up to 10.
  • When your site has used this hour's API budget, the app says so at the top of the page with the time when new documents can start again. My documents, Cancel and Delete keep working.
  • A single work item that is too large for a background document (very long text or many long comments) is left out and listed as "too large".
  • Clicking Generate twice by accident does not start a second document — the app shows the existing one.
  • A background document keeps the template version it started with, even if an admin uploads a new version meanwhile.
  • Delete now removes the collected data immediately. Cancel stops collecting and deletes what was collected.
  • Only you can render your background documents. Jira admins can cancel or delete them (Usage → Background documents in the app's settings) but cannot read their content. If an admin deletes your background document, it disappears from My documents and can no longer be rendered or downloaded.
  • Rendering in the browser needs a current version of Chrome, Edge or Firefox.

Tips for large documents

  • DOCX and XLSX are faster and lighter than PDF.
  • If your browser runs out of memory, try fewer work items, DOCX instead of PDF, or a background document.
  • For flat lists of many thousands of work items, Jira's own CSV export may fit better; see Large sites.
