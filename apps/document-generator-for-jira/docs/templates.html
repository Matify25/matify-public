Template cookbook

Document Generator fills your own Word template (.docx) with Jira data. You put placeholders such as {{summary}} into the Word file, upload it, and the validator tells you — before anyone uses the template — what will render, what is wrong and what PDF output can and cannot reproduce.

The placeholder language is called TL1. It is deliberately small: values, rich text, sections (loops), groups, simple conditions, counts and images. There are no expressions, no scripting and no arithmetic. Anything that is not described on this page is not supported, and the validator rejects it.

Every validator finding links to its own section on this page (for example E-007).

A first template in two minutes

  1. Open Word and type:
    {{key}} – {{summary}}
Status: {{status}} · Assignee: {{assignee|ifempty:Unassigned}}
Due: {{duedate|date:dd.MM.yyyy|ifempty:–}}

{{@rich:description}}
  2. Save it as a Word Document (.docx).
  3. In Jira settings → Apps → Document Generator → Templates, upload it. The validator checks it and shows a report.
  4. Use Preview with sample with a real work item key to see what each placeholder resolves to, then publish the template to your projects.

The easiest way to learn TL1 is to download one of the four curated packs (Jira settings → Apps → Document Generator → Packs → "Download to customise") and look at its placeholders in Word.

Basics

  • Placeholders start with {{ and end with }}.
  • Tags are case-sensitive: {{summary}} works, {{Summary}} does not.
  • Spaces inside the braces are ignored: {{ summary }} is the same as {{summary}}.
  • Type each placeholder in one go, in one paragraph. Word sometimes splits text that was edited in pieces; a placeholder split across paragraphs or text boxes is reported as E-001. Retyping the placeholder fixes it.
  • A stray {{ or }} is an error (E-001).
  • A template may contain at most 500 placeholders (E-006).
  • Placeholders work in the body, in headers and footers, and as plain value tags (such as {{doc.title}}) in the document properties (title, subject …). Sections and other tag kinds are not allowed in document properties (E-001).

Value tags

A value tag shows one value as text, formatted with the style of the paragraph it sits in.

Dates without a format follow the site's Default date format (Jira settings → Apps → Document Generator → Settings): it applies to date fields such as {{duedate}} and date custom fields, to {{doc.date}} and to any field with |date (for example {{created|date}}). With the default setting ("Each user's Jira language") these dates use the medium date format of the generating user's Jira language. Date-time fields without a format ({{created}}, {{updated}}, {{resolutiondate}}) and |datetime always show the user's Jira language style with the time, in their time zone. A pattern in the placeholder (|date:dd.MM.yyyy) always wins. Date-only fields such as the due date never shift across time zones.

Custom fields

Use either the field id or the exact field name:

  • {{customfield_10016}} — by id. Ids are stable; this is the safest form.
  • {{cf:Story Points}} — by exact name. The validator looks the name up in your site's field list. If two custom fields have the same name, it reports E-003 and lists the ids to use instead.

Rich text

{{@rich:description}} inserts the field with its formatting. It works with description, environment and multi-line (paragraph) custom fields, e.g. {{@rich:customfield_10050}}. Inside {{#comments}}, {{@rich:body}} inserts the comment text with formatting.

A rich-text tag must be the only content of its paragraph — no other text, no spaces (E-004). Using it on a single-line field is reported as E-002.

Sections

A section repeats or shows a part of the template. It starts with {{#NAME}} and ends with {{/NAME}}. Close sections in the reverse order you opened them.

The work items of the document: issues

{{#issues}}
{{key}} {{summary}} ({{status}})
{{/issues}}

{{#issues}} repeats its content once per work item, in document order: the order of your JQL (when the JQL has no ORDER BY, Document Generator sorts by key), or the selection order when Jira passes selected work items to the app (from the issue navigator Jira currently passes the search only). A single-item document has exactly one item.

Per work item collections

Inside {{#issues}} (or in a single-item template) you can loop over a work item's related data:

SectionRepeats overAvailable inside
{{#subtasks}}Sub-tasks (filled when "+ sub-tasks" is chosen when generating)All work item fields of the sub-task
{{#children}}Child work items (filled when "Epic + children + sub-tasks" is chosen)All work item fields of the child
{{#links}}Linked work items{{linkType}}, {{direction}}, {{key}}, {{summary}}, {{status}}, {{url}}
{{#attachments}}Attachments{{filename}}, {{size}}, {{created}}, {{author}}, {{mimeType}}, {{%image}}
{{#comments}}Comments (only when "Include comments" is chosen when generating){{author}}, {{created}}, {{@rich:body}}

{{size}} shows a readable size such as "12 KB" or "1.2 MB"; {{size|number:0}} shows the raw number of bytes. {{direction}} reads from the work item's point of view, e.g. "blocks" or "is blocked by". Comments are the most recent ones, newest first, up to the limits your Jira admin set (10 per work item by default).

Inside a collection, tags that are not members of that collection fall back to the enclosing work item, and then to the document. A sub-task answers every work item field itself — it never shows its parent's assignee.

Inverted sections

{{^NAME}}…{{/NAME}} shows its content only when the collection is empty:

{{#attachments}}{{filename}} ({{size}}){{/attachments}}
{{^attachments}}No attachments.{{/attachments}}

Nesting

Sections may be nested at most two levels below the document: document → {{#issues}} → one per-item collection. {{#issues}} itself must be at document level or directly inside {{#group:…}}. Collections cannot be placed inside attachments, comments or links. Breaking these rules is reported as E-005.

Tables that repeat rows

Put the section tags in a table row and the row repeats:

KeySummaryStatus
{{#issues}}{{key}}{{summary}}{{status}}{{/issues}}

The first cell starts the section, the last cell ends it. Mark the table's first row as a header row in Word ("Repeat as header row at the top of each page") and it repeats on every page in DOCX and PDF. A section that starts in a table row must end in the same row, or wrap whole rows (E-001).

One page per work item

Put a Word page break (Ctrl+Enter) at the end of the {{#issues}} body, just before {{/issues}}. Every work item then starts on a new page. There is no page-break placeholder; page breaks you place in Word are kept.

Grouping

{{#group:FIELD}}…{{/group:FIELD}} splits the document's work items into groups. Inside a group, {{groupName}} and {{groupCount}} describe the group and {{#issues}} repeats over the group's work items.

You can group by issuetype, status, statusCategory, fixVersions or components.

{{#group:issuetype}}
{{groupName}} ({{groupCount}})
{{#issues}}{{key}} {{summary}}{{/issues}}
{{/group:issuetype}}
  • Group order: status categories To Do → In Progress → Done; statuses by category, then by first appearance; all other fields by first appearance.
  • Work items without a value go to a group named "(none)", which comes last.
  • Multi-value fields (fix versions, components) put a work item into every group it belongs to.
  • Groups must be at document level and cannot be nested (E-005). {{groupName}} outside a group is E-001.

Grouping by any other field (priority, assignee, parent, project, resolution, labels …) is not supported in this version (E-001).

Conditions

{{#has:FIELD}}…{{/has:FIELD}} shows its content only when the field has a value; {{^has:FIELD}}…{{/has:FIELD}} only when it is empty.

{{#has:duedate}}Due {{duedate|date}}{{/has:duedate}}
{{^has:assignee}}This work item is not assigned.{{/has:assignee}}

FIELD can be any work item field, custom field (customfield_10016 or cf:Name), collection name (has:attachments), collection member, or document tag (has:doc.notes). There is no else-if, no and/or and no comparison. Conditions of the form is:FIELD=VALUE are not supported in this version (E-001).

Counts and percentages

TagWhereShows
{{count:subtasks}}, {{count:children}}, {{count:comments}}, {{count:attachments}}, {{count:links}}Per work itemHow many the work item has (as included in the document)
{{count:FIELD=VALUE}}Document or group levelHow many work items have that value. FIELD is one of issuetype, status, statusCategory, fixVersions, components.

Values are compared without regard to upper or lower case. Because status category names are translated into each user's Jira language, statusCategory also accepts the category keys new, indeterminate and done, which work in every language:

Done: {{count:statusCategory=done}} ({{percent:statusCategory=done}} %)
In progress: {{count:statusCategory=indeterminate}}
Overdue: {{count:overdue}}

Document-level counts placed inside {{#issues}} are reported as E-001. percent: on other fields is not supported in this version.

Images

  • {{%image}} inside {{#attachments}} inserts that attachment if it is an image.
  • {{%image:first}} at work item level inserts the work item's first image attachment.
  • Images inside rich text (for example a screenshot pasted into the description) are embedded when they are attachments of the same work item.
{{#attachments}}
{{filename}}
{{%image}}
{{/attachments}}

Rules:

  • PNG and JPEG are embedded (checked by file type and content). Other image types (GIF, SVG, WebP, HEIC …) and images that cannot be loaded appear as "[image: filename]". A {{%image}} on an attachment that is not an image (for example a PDF) renders nothing; its name is still listed by {{filename}}.
  • Each image may be up to 5 MB. Per document: up to 10 images per work item, 200 images and 100 MB of image data (your Jira admin can lower the counts).
  • Images are scaled to the text width (or the table cell width) and to at most 60 % of the page height, keeping their proportions.
  • Every image that is not embedded is listed in the result and in {{doc.notes}}.
  • Images are fetched by your browser, with your permissions, when the document is built. They are never stored by the app.

Single-item and list templates

A template's scope is set when it is published: single work item, lists of work items, or both.

  • List templates put work item tags inside {{#issues}}.
  • Single-item templates may use work item tags directly in the body, without {{#issues}}. Such tags only show a value when the document contains exactly one work item; in a list document they stay empty. The validator warns about them with W-202.

PDF output

PDF fidelity statement:

PDF is produced by Matify's built-in converter from your filled Word document. It reproduces a documented subset: paragraphs and character formatting applied directly or through paragraph styles, headings, bullet/numbered lists up to 3 levels, tables with borders and shading set on the table or cells, merged cells and repeated header rows, images, page breaks, margins and page size, and simple headers/footers with page numbers. Word table styles are approximated (grid borders, bold header row). PDF text is set in the bundled Noto Sans fonts, so line breaks and page count can differ from Word. Use DOCX for the exact layout.

The same statement appears as an info line (I-001) in every validator report.

Not reproduced in PDF (DOCX is unaffected; the validator warns about each one): text boxes, floating (anchored) pictures and shapes, SmartArt, charts, multiple text columns, different first-page or odd/even headers, Word fields other than page numbers (they show their last saved result), content controls (reduced to their text), tracked changes, Word comments, footnotes and endnotes, embedded fonts, equations, legacy (VML) shapes and watermarks, and pictures that are not PNG or JPEG. With several sections, only the page size and margins of the last section are used.

Further PDF limits:

  • A heading can end up alone at the bottom of a page (there is no "keep with next").
  • Row heights and vertical alignment in table cells are ignored; only the default header and footer are used.
  • JPEG orientation stored in the camera's EXIF data is ignored, so a photo can appear rotated.
  • Fonts cover Latin (including Latin Extended), Greek and Cyrillic. Chinese, Japanese, Korean, Arabic, Hebrew, Thai and Devanagari text cannot be shown in PDF, and some symbols (for example "→") are missing from the bundled font. Missing characters are listed with the result; use DOCX for such documents.
  • Your template's fonts (Calibri, Aptos, Arial …) are replaced by Noto Sans; code is set in Noto Sans Mono.
  • The PDF paper size is A4 or Letter, as your Jira admin set it for the site or for the template. Orientation and margins come from your Word template.
  • PDF output is not tagged for accessibility. Word's own "Save as PDF" remains available for the DOCX.

Excel (XLSX) output

XLSX output is a table, not a filled Word template:

  • One sheet named "Work items", one row per work item in document order, a frozen header row, an autofilter and set column widths.
  • Curated packs bring their own column set.
  • Your own templates get one column per work item value tag used in the template, in template order, starting with Key.
  • Dates are real Excel dates and numbers are real numbers. Rich text is exported as plain text.
  • A cell holds at most 32,767 characters; longer text is cut with "…" and listed in the notes.
  • Values that start with =, +, - or @ are written as text, so Excel never runs them as formulas.

File names

Your Jira admin sets a file-name pattern (default {template}-{scope}-{date}) built from {template}, {scope}, {date}, {key} and {format} plus plain text. File names are cleaned of characters that are not allowed in file names and are at most 120 characters long.

Validator codes

Every finding shows its code, where it is (body, header or footer, and the paragraph with an excerpt) and an explanation. Errors (E) make a template Invalid: it cannot be published. Warnings (W) make it Valid with warnings: it can be published, and users get the output described in the warning. Info lines (I) need no action.

E-001 — Template syntax error

The placeholder text cannot be read. The message names the reason, for example:

  • {{ without }}, or }} without {{;
  • a placeholder split across paragraphs or text boxes;
  • a section that is never closed, closed without being opened, or closed in the wrong order;
  • an unknown tag kind, format, date pattern or document tag;
  • {{%image}} outside {{#attachments}}, {{@rich:body}} outside {{#comments}}, {{groupName}} outside a group, a document-level count inside {{#issues}};
  • a section that starts inside a table and ends outside it;
  • section or other non-value tags in the document properties;
  • features that are not supported in this version: is: conditions, grouping or count: on fields other than issuetype, status, statusCategory, fixVersions and components, percent: on fields other than statusCategory, and change history (history / history:FIELDS).

Fix: go to the paragraph shown in the report, retype the placeholder in one go, and check the spelling against this page.

E-002 — Unknown field

"'{tag}' doesn't match a field on this site. Check the spelling or use the field id (for example customfield_10016)." The report suggests similar field names where it finds them. E-002 is also reported when {{@rich:…}} is used on a field that is not multi-line text.

Fix: use the exact field id or the exact custom field name with cf:. The message lists similar fields as "Name (id)" when it finds any. For a single-line field, use a value tag ({{field}}) instead of {{@rich:field}}.

E-003 — Ambiguous custom field name

Two or more custom fields on your site have the name used after cf:. The message lists their ids.

Fix: replace {{cf:Name}} by the field id, e.g. {{customfield_10016}}.

E-004 — Rich-text tag is not alone in its paragraph

{{@rich:…}} must be the only content of its paragraph, without other text or spaces, and must not be inside an inline section.

Fix: put the rich-text tag on its own line (its own paragraph).

E-005 — Sections nested too deeply or in an invalid place

Sections may be nested at most two levels below the document (document → issues → one per-item collection). {{#issues}} must be at document level or directly inside a group; collections cannot be inside attachments, comments or links; groups cannot be nested or placed inside another section.

Fix: move the section so that the nesting rules in Nesting hold.

E-006 — Too many tags

The template contains more than 500 placeholders.

Fix: remove placeholders, or split the template into two.

E-007 — Unsafe content

The file contains content that can run code, load external content or hide data. Document Generator rejects:

  • macros (VBA projects, macro-enabled files .docm/.dotm, ribbon or keyboard customisations);
  • encrypted or password-protected files, write protection and enforced "Restrict Editing";
  • links to external content other than ordinary hyperlinks (for example linked pictures);
  • hyperlinks that are not web or e-mail addresses: only http:, https:, mailto: and links within the document (#bookmark) are allowed. Links to files or network shares (file:, UNC paths such as \\server\share), javascript:, data: and links that start programs (for example ms-msdt:) are rejected;
  • a hyperlink base (File → Info → Properties → Hyperlink base) that points to a file location or network share instead of an https:// address;
  • mail-merge settings (a data source or SQL query that Word would offer to run when the document opens) — restore the document with Mailings → Start Mail Merge → Normal Word Document;
  • the field codes INCLUDEPICTURE, INCLUDETEXT, the older INCLUDE, LINK, DDE, DDEAUTO, IMPORT and DATABASE, also when the field name is in quotes ("INCLUDEPICTURE" …) or split across several pieces of text in the same field code;
  • field codes that are built from other fields: any field whose code contains another field (for example { IF { MERGEFIELD … } … }, { = { PAGE } - 1 } or { {QUOTE …} … }), and QUOTE and SET fields in any form — Word can assemble a forbidden field code from them without its name appearing in the file. Fields inside another field's result (for example the page numbers of a table of contents) are fine, and plain REF, PAGEREF, PAGE, NUMPAGES and DATE fields without fields inside them stay allowed;
  • imported content chunks (altChunk), embedded OLE objects and packages (also a package stored outside the usual word/embeddings folder), ActiveX controls, sub-documents (master documents), frames and framesets, attached templates, and XML document type declarations.

The check reads every XML part of the file — not only the parts with the usual names — so moving content to an unusual part name or location does not hide it. Charts are allowed (their data workbook is not active content); they are only a PDF warning (W-105). Pictures, including SVG logos, are not affected.

Stricter checks (October 2026): a template that an earlier build of the app accepted can now be rejected — at upload, and by the output check below when documents are generated from it — if it contains one of the newer items above (for example a file: link, a hyperlink base on a file share or mail-merge settings). The validator message names the element; fix it and upload the template again.

The same check runs on every filled Word document before it is downloaded or attached, including the Word document a PDF is converted from. If a filled document fails the check, it is blocked and not downloaded (customer message: "The finished document contained content that Document Generator blocks for safety …").

Fix: remove the element named in the message (Alt+F9 in Word shows field codes; Developer → Document Template shows an attached template), save as a Word Document (.docx) and upload again.

E-008 — File, size or compression check failed

The file is not a usable .docx: not a Word document, a legacy Word 97–2003 (.doc) file, damaged, missing required parts, larger than 5 MB, larger than 50 MB when unpacked, more than 2,000 parts, suspicious compression (zip-bomb guard), invalid part names, unsupported compression or unreadable XML.

The compression check (zip-bomb guard) runs at upload and again in the browser each time a document is generated from the stored template, before the file is unpacked. A stored template that fails it cannot be used for documents (customer message for code DGJ-TPL-E-008).

Fix: open the file in Word, save it as Word Document (.docx), remove large embedded media, and upload again.

W-101 — PDF: Word table style is approximated

A Word table style (other than "Table Grid") is shown in PDF with grid borders and a bold header row. Fix (optional): set borders and shading directly on the table for an exact PDF.

W-102 — PDF: text box is not reproduced

Text boxes are missing from PDF output. Fix (optional): move the content into normal paragraphs or a table.

W-103 — PDF: floating drawing is not reproduced

Floating (anchored) pictures and shapes are missing from PDF. Fix (optional): set pictures to "In line with text".

W-104 — PDF: SmartArt is not reproduced

Fix (optional): replace SmartArt with a picture or a table.

W-105 — PDF: chart is not reproduced

Fix (optional): paste the chart as a picture, or use DOCX output.

W-106 — PDF: multiple columns are not reproduced

The PDF uses one column. Fix (optional): use a table for side-by-side content.

W-107 — PDF: different first-page or odd/even headers are not reproduced

The default header and footer are used on every PDF page.

W-108 — PDF: Word field shows its last result only

Word fields such as DATE or TOC show the result Word saved last; only page numbers (PAGE, NUMPAGES) are computed. Fix (optional): use {{doc.date}} instead of a DATE field.

W-109 — PDF: content control is reduced to its text

W-110 — PDF: tracked changes are not reproduced

Fix: accept or reject all changes before uploading.

W-111 — PDF: comments are not reproduced

Word comments in the template are not shown in PDF. Fix: delete them before uploading.

W-112 — PDF: footnotes and endnotes are not reproduced

W-113 — PDF: embedded fonts are not used

PDF text is set in Noto Sans.

W-114 — PDF: script not covered by the PDF fonts

The template contains Chinese/Japanese/Korean, Arabic, Hebrew, Thai or Devanagari text. PDF fonts cover Latin, Greek and Cyrillic only. Fix: use DOCX for this template.

W-115 — PDF: only the last section page setup is used

The document has several sections; PDF uses the page size and margins of the last one.

W-116 — PDF: equations are not reproduced

W-117 — PDF: image format is not reproduced

A picture in the template is not PNG or JPEG and is left out of the PDF. Fix (optional): insert it as PNG or JPEG.

W-118 — PDF: legacy shape or object is not reproduced

Legacy shapes, watermarks and objects (VML) are missing from PDF.

W-201 — Field type is not fully supported

The field's type is not one of the types in Custom fields. It shows the first of value / name / display name, or stays empty. Fix: check the preview; use a different field if the value is not useful.

W-202 — Work-item tag outside {{#issues}}

A work item tag stands outside {{#issues}}. It shows a value only when the document contains exactly one work item. Fix: fine for single-item templates; for list templates, move the tag inside {{#issues}}.

W-203 — Format has no effect on this field

A date format on a field that is not a date, or a number format on a field that is not a number. Fix: remove the format or use it on a matching field.

I-001 — PDF fidelity

Every report shows the PDF fidelity statement (see PDF output). No action needed.

I-002 — Field resolution skipped

The site's field list could not be loaded, so field names were not checked. Fix: upload the template again later so that fields are checked before you publish.

I-003 — Uses an opt-in collection

The template shows comments or child work items. They are included only when "Include comments" or the epic hierarchy is chosen when generating. No action needed.

Template management messages

These codes appear in the admin pages or when a document is built. They link here from the app.

DGJ-TPL-E-001

A template syntax error was found while a document was built. The template should have been validated; ask your Jira admin to open it, check the validation report (E-001) and upload a corrected version.

DGJ-TPL-E-004

A rich-text tag is not alone in its paragraph (E-004), found while a document was built. Ask your Jira admin to fix the template.

DGJ-TPL-E-006

"This template has too many placeholders to store. Split it into smaller templates (see E-006)." Shown during upload when the template's placeholder list is too large to save. See E-006.

DGJ-TPL-E-007

The finished document contained content that Document Generator blocks for safety (for example a remote link or a macro); it was not downloaded or attached. See E-007; ask your Jira admin to check the template.

DGJ-TPL-E-008

"Word templates can be up to 5 MB." See E-008.

DGJ-TPL-NOTFOUND

The template or template version was not found — it may have been deleted, or the version is no longer the current or previous one. A background document whose template was deleted cannot finish. Fix: pick another template, or ask your Jira admin.

DGJ-TPL-INVALID

"Only valid templates can be published. Fix the errors in the validator report and upload a new version."

DGJ-TPL-HASH

"The uploaded file didn't arrive completely. Upload it again."

DGJ-TPL-UPLOAD

The upload expired (uploads are kept open for 30 minutes) or a part of it was not valid. Fix: upload the template again.

DGJ-TPL-STATE

The action does not fit the template's state, for example: an archived template must be restored before a new version is uploaded; a template needs an uploaded version before it can be published; the current version cannot be deleted.

DGJ-TPL-PINNED

"A background document still uses this template (or version). Delete it or wait until it expires (24 h)." Background documents keep the template version they started with until they expire.
