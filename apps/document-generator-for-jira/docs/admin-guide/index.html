Admin guide

Administration lives in Jira settings → Apps → Document Generator, with the pages Overview, Templates, Packs, Settings and Usage. Only Jira administrators (global permission Administer Jira) can use them. The app checks this permission on the server for every admin action, with your own Jira permissions, so hiding the menu is not the only protection.

Overview

The Overview page shows:

  • Status: licence, who may generate documents, how much of this site's API budget was used this hour, and the state of Jira's shared API limit for apps.
  • Numbers: documents this month, background documents running or queued, failures in the last 30 days.
  • Needs attention: invalid templates and failed background documents.
  • A summary of the current settings, and the Get started checklist (which you can dismiss).

Versions

Document Generator keeps the current and the previous version of every template, plus any version a background document still uses (a background document keeps the version it started with). Older versions are removed when you upload a new one. You can delete a version that is neither current nor in use.

What users see

Users only see published templates and enabled packs that fit what they are doing:

  • Scope: single-item templates are offered for a work item, list templates for searches; templates for both are offered everywhere.
  • Projects: a template assigned to selected projects is offered in the work item dialog only on work items of those projects. For searches, the app checks every collected work item on the server: work items of projects the template is not assigned to are left out and listed.
  • Formats: only formats allowed by both the template and the site settings.

Validator

The validator report lists errors (the template is Invalid and can't be published), warnings (Valid with warnings) and information. Each finding shows the code, the location (body, header or footer, the paragraph and an excerpt), an explanation and a link to the Template cookbook. Every report also shows the PDF fidelity statement.

The validator also blocks unsafe files: macros, encryption and password protection, links to external content, field codes that load external content (INCLUDEPICTURE, INCLUDETEXT, LINK, DDE, DDEAUTO, IMPORT, DATABASE), imported chunks, OLE and ActiveX objects, sub-documents, frames and attached templates — see E-007. The same check runs again on every filled Word document before a user can download or attach it.

If the field list could not be loaded, field names are not checked (information line I-002); upload again later before you publish.

Preview with sample

On a template's Preview tab, run the template against one work item key or a JQL (the first 20 work items). The preview reads Jira with your permissions and works on drafts too. It shows:

  • every placeholder with the value it resolves to (an excerpt of up to 200 characters, shown as plain text) and notes;
  • fidelity notes from rich text (for example an app macro that was left out);
  • the images found and whether each will be embedded or shown as a placeholder, with the reason;
  • time taken and API points used;
  • Download sample buttons for DOCX, PDF and XLSX.

Nothing from the preview is stored.

Packs

Four curated packs ship with the app: Release notes, Status report, Work item record and Test evidence. They are validated with no warnings, designed to work in PDF, and come with their own Excel column set. Descriptions and sample PDFs are on the documentation start page.

On the Packs page you can:

  • switch each pack on or off for your site (all four are on after installation);
  • Download to customise — save the pack's .docx, edit it in Word, and upload it as your own template;
  • download samples made with fictitious data.

Limits can only be lowered below their maximum. The maximum of each limit is the upper end of its range above; values above it are refused when you save, and a stored value can never raise a limit beyond it. All defaults equal the maximum, except comments per work item: it starts at 10 and can be set up to 20.

Note on the default date format: it applies to every date shown without a pattern of its own — date fields such as {{duedate}}, {{doc.date}} and fields with |date — in documents generated after you save it. Date-time fields without a format ({{created}}, {{updated}}) and |datetime keep each user's Jira language style with the time. A pattern in the placeholder, for example {{created|date:dd.MM.yyyy}}, always wins (formats).

Usage

The Usage page counts documents per month, format, entry point (work item, search, Documents page) and template kind (the pack, or "custom template"): documents, work items, attach-backs, background documents, failures and cancellations. It contains no personal data — no names, account IDs or work item content — and covers up to 24 months. Filter by month range.

Background documents of all users

The Usage page also lists the Background documents of everyone on the site, newest first: state, template, format(s), work items staged of the total, created and updated time, and "Started by" — You or Another user. Filter by state: All, Active (queued, waiting for budget, collecting), Ready (ready, downloaded, attached) or Finished (failed, cancelled, expired). "All" shows the 100 most recently updated; choose a state to page through all of them with Load more.

  • Cancel (active documents only, after confirmation) stops collecting and deletes the data collected so far. The person who started it sees it as Cancelled.
  • Delete (after confirmation) removes the background document and its staged data now; an active document is cancelled first. The person who started it can no longer render or download it, and it disappears from their My documents list. Files already downloaded or attached to work items are not affected.

Use this, for example, for a document that blocks the queue. Jira admins cannot read a background document's content, its scope text or who started it: there is no open, render or download action for other people's documents, and collected data can only be rendered by the person who started the document.

Licence

Without an active licence or trial, nobody can generate new documents or start background documents. Data portability and deletion outlive the subscription:

  • Admin pages are read-only. Overview, Templates (details, validation reports, versions), Packs, Settings and Usage stay readable, and a banner explains the licence state. Saving settings, uploading templates or new versions, editing template details, publishing, restoring archived templates, switching packs on or off and the sample preview are disabled.
  • Still available: Download of every kept template version, Unpublish, Archive, Delete of templates and versions, Cancel and Delete of background documents, and Delete all app data — so you can always take your templates with you and remove your data.
  • Background documents: queued and running ones are cancelled at their next step, and the collected data of documents that were ready is deleted by the next daily cleanup (they show as Cancelled). Nobody can render, download or attach them any more, and Retry is unavailable. Each person can still see, cancel and delete their own background documents under Apps → Document Generator → My documents. Files that were already downloaded or attached to work items are not affected.

After a renewal or a new trial everything is available again; cancelled background documents have to be generated again.

Delete all app data

Settings → Delete all app data…. After you type DELETE to confirm, the app removes all templates and their versions, all background documents and their collected data, the usage counters and the settings (they return to the defaults), as well as its caches and API budget records. The deletion runs in the background and shows its progress; while it runs, the rest of the app is unavailable ("Document Generator is deleting all app data") and nothing new is stored. A final check runs over all of the app's storage before the deletion reports that it has finished; then nothing the app stored is left. When someone opens the app again afterwards, it creates only its small operational records again (installation time, storage version, permission check cache, the current hour's API budget counter) — never templates, documents or settings.

Documents attached to work items are Jira attachments and stay in Jira. Download the template versions you want to keep first.

Uninstalling

When the app is uninstalled, it first cancels open background documents and deletes their collected data (best effort; this never blocks the uninstall). Everything else the app stored — templates, settings, usage counters, job records — then follows Atlassian's data lifecycle for Forge apps: Atlassian keeps app data for a limited period after an uninstall (28 days at the time of writing) and then deletes it.

Reinstalling creates a new installation. Do not rely on getting your templates back after a reinstall: download every template version you want to keep before uninstalling. Attachments that users created stay in Jira.

To remove the app's data right away, use Delete all app data before uninstalling.
