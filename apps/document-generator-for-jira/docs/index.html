Document Generator for Jira — documentation

Document Generator turns one Jira work item, a JQL search or an epic with its children into a Word (DOCX), PDF or Excel (XLSX) document — filled from your own Word template or from one of four curated packs. A validator checks every template before anyone uses it, limits are shown before a document starts, and large lists run in the background.

Published by Matify for Jira Cloud. Support: support@matifyapps.de.

Limits at a glance

LimitValue
Work items generated directly in the browserUp to 200 (50 when comments are included)
Work items in a background documentUp to 1,000 (DOCX, PDF and XLSX)
CommentsUp to 500 work items per document, the 10 most recent per work item (admins can set 1–20)
ImagesPNG and JPEG, up to 5 MB each, 10 per work item, 200 and 100 MB per document
Template file.docx up to 5 MB, at most 500 placeholders
Background documentsKept 24 hours after they are ready; up to 3 in progress per person and 10 per site
API budget6,000 points per hour per site (admins can lower it)

Jira administrators can lower these limits; see the admin guide. Why the limits exist is explained in Large sites.

Curated packs

Four ready-made templates, validated with no warnings. Samples use fictitious data.

PackForSample
Release notesLists: work items grouped by type with key, summary, status, fix versions and an optional description. Typical scope: a fix version.PDF
Status reportLists or an epic with its children: counts and shares by status category, overdue work items, a table with status, assignee and due date, and descriptions.PDF
Work item recordOne work item: key fields, rich description, sub-tasks, linked work items, attached images, optional comments and plain-text sign-off lines. Suitable for change records.PDF
Test evidenceOne or more work items, one page each: description and steps, status, environment, fix version and image attachments as evidence screenshots. Work item content only.PDF

The three facts

  • No Jira content or personal data leaves Atlassian. Matify sees only anonymous usage counts in Forge logs, and only if your admin allows app log access.
  • Documents are generated in your browser and are not stored by the app unless you attach them to a work item.
  • Every read uses the permissions of the person generating the document.
